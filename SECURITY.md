# Безопасность BOOKROOM

## Модель доступа
- **Гость**: читает только опубликованные студии. Пишет только через RPC (`book_appointment`, `*_by_token`, `submit_review`); прямые INSERT/UPDATE/DELETE для `anon` отозваны.
- **Клиент**: видит свои записи (связка по *подтверждённому* телефону/email из `auth.users`). В профиле может менять только имя, телефон, аватар, ник в Telegram и настройки уведомлений.
- **Сотрудник (staff)**: видит свои записи, может менять только их статус (подтверждена / завершена / неявка) и заметку.
- **Админ / владелец**: всё в рамках своей студии (RLS по `has_studio_role`). Последнего владельца удалить нельзя.
- **Админ платформы**: только по подтверждённому email из `platform_admin_emails`. Доступ к чужим данным только через SECURITY DEFINER-функции `platform_*` с проверкой прав внутри; персональные данные клиентов студий не отдаются.

## Защиты
- RLS на всех таблицах; SECURITY DEFINER-функции с `search_path = ''`; служебные функции недоступны через API.
- Двойная запись невозможна: exclusion constraint `appointments_no_overlap`.
- Антиспам онлайн-записи: не больше 3 активных записей клиента в студию, 5 в час, 30 записей на студию за 10 минут.
- Лимиты входа по коду (`[auth.rate_limit]`), код живёт 15 минут, повторная отправка не чаще раза в минуту.
- Загрузки: тип файла определяется по содержимому (JPG/PNG/WebP/AVIF), SVG и HTML отклоняются; лимит 5 МБ; путь привязан к студии.
- Ссылки студии: в базе разрешены только `http(s)://` (нет `javascript:`).
- Приватные ссылки на запись: случайный UUID, `no-store`, `no-referrer`, `noindex`.
- Заголовки: CSP, HSTS (prod), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, COOP.
- Server Actions: встроенная проверка Origin в Next.js; редиректы после входа только на внутренние пути.

## Перед запуском в прод
1. `SUPABASE_SERVICE_ROLE_KEY` только в переменных сервера, никогда с префиксом `NEXT_PUBLIC_`.
2. В Supabase → Auth: включить CAPTCHA (Cloudflare Turnstile или hCaptcha), свой SMTP и SMS-провайдера, удалить тестовые номера `test_otp`.
3. Site URL и Redirect URLs: только ваш домен.
4. Не загружать `seed.sql` в прод (демо-пароли). Админов платформы задать через `platform_admin_emails`.
5. Включить Point-in-Time Recovery / бэкапы.
